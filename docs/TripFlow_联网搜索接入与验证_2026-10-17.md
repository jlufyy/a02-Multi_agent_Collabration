# TripFlow 联网搜索接入与验证

日期：2026-10-17。本轮已修改代码、重新构建前端并重启本机 8010 服务。

## 配置与原因

用户本次新增的是腾讯云 WSA 服务 API Key，最初保存在根目录 `(1).env`。后端配置入口只读取根目录 `.env`，且原实现没有 WSA 适配，因此仅保存该文件无法启用搜索。本轮已将 `TENCENTCLOUD_WSA_APIKEY`、`TENCENTCLOUD_WSA_API_URL` 同步到被 Git 忽略的 `.env`，保留其他配置。后续统一修改 `.env` 并重启后端即可。

腾讯云采用服务 API Key 的 Bearer 方式，请求与结果解析遵循 [官方接入文档](https://cloud.tencent.com/document/product/1806/130615)。密钥只在后端使用，没有写入前端、响应、测试证据或本报告。补充了腾讯云、Tavily、博查的适配；本轮真实验证的是腾讯云。

## 已实现

- 生成行程时，为已选活动查询与到访日期相关的开放时间、门票、预约资料；关联结果随行程保存。仅发送公开地点名称、城市和到访日期。
- 每次规划最多查询 12 个不同景点，并发上限 3，总检索时限 25 秒；每次搜索限时 8 秒，保留最多 3 条匹配来源。服务异常、额度不足和无匹配结果均保留现有行程，并给出中文提示。
- 已有行程可以从景点详情点击“联网查资料”或“重新搜索”。该次结果在当前详情面板展示，不直接改动已确认计划。新接口为 `POST /api/v1/places/research`。
- 个性化内容准备复用规划中的联网资料，保留所引用来源。搜索摘要被视为外部参考，不会执行其中的指令。
- 规划核验和修改预览使用统一中文提示，按景点合并营业时间、费用及预约待确认事项。页面不显示内部诊断码、活动 ID、调用名称和追踪编号。错误提示、服务状态及来源展示同步调整。
