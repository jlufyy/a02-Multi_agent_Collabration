# TripFlow 体验优化与验证

开发基线：2026-10-17 实时核对 GitHub `main` 与本地 HEAD，均为 `9fa9370594ec0ca3abfca46b916139365d5c1872`。本次交付包含以下体验优化，未部署远端服务。默认入口仍是自然语言需求、多轮 AI 理解、摘要确认、自动规划；高级表单保留作可选编辑。

## 修改

- 冲突预览可直接改日期、开始时间、游览时长或移除非必去活动，重新计算后再次确认。保留原待确认草稿直到新提案成功，避免网络失败丢失修改。锁定、预约、固定条件和进行中的活动继续受到保护。
- 高德 `biz_ext.opentime2/open_time` 和照片不再丢弃；日期解析支持常见跨年淡旺季、月份组合、周次、24 小时、最后入园说明。复杂节假日例外无法确定时继续待核验。
- 门票从故宫官网、北京旅游网的已审核景区页提取，保留 URL 和读取时间，按日期选成人普通大门票；不使用人均消费代替票价，不把抓取失败当作免费。其他地点只对有明确匹配的政府页面尝试通用提取。不能保证任意景点的所有票种、优惠资格和临时政策均可自动核验。
- 新计划保存照片 URL，旧计划可按原 POI ID 补载。图片失败逐张回退，最终显示明确的景观示意，无名称首字大色块。
- 候选景点按区域分天，默认目标每日最多 4 站，低步行偏好保持最多 2 站；保留午休及真实路程。比较用户允许的交通方式，避免直接采用第一条耗时很长的步行路线；可选长途绕行优先尝试替换为附近真实景点。必去、固定安排不会被偷偷删除。
- 相邻活动留出 5 分钟交通衔接缓冲。最终复核发现每段不超过 2 分钟、200 米、总时长差不超过 5 分钟的路线波动时，仍以最新路线独立检查原活动时段；只有同样交通方式且复核可提交，才允许保留原预览时段确认。明显变化、不可达、缺少可信路线仍需重新预览。此逻辑不会自动改写用户确认的活动时段。
- DeepSeek A1 的复杂需求曾出现 `finish_reason=length`，4096 个输出 token 中 4048 个用于内部推理。A1 直连默认显式关闭思考模式，把预算留给结构化结果；Schema 校验与有界修复继续保留。相同复杂需求直接调用复测约 2.36 秒成功，一次识别日期、人数、预算、交通及两个必去地点。这是一次实测耗时，不是性能保证。
- 多轮编辑将助手的澄清问题与选项一并传入后续上下文，避免用户回答“选 A”时丢失 A 的含义。核验资料更新不会再被显示成所有活动的游览时间变更；无冲突的微调控件默认折叠。

- 后端 195 项、前端 41 项、定位上下文 23 项测试通过；前端类型检查、ESLint、生产构建和生成契约检查通过。
- 真实地图与官网调用：八达岭、故宫、天坛、颐和园均取得 3 张地点图片 URL；验证了 2026-10-20 与 2026-11-03 两个季节的普通门票。故宫 60/40、八达岭 40/35、天坛 15/10、颐和园 30/20 元/人。原始记录在本机忽略目录 `output/live-place-facts.json`。
- 浏览器从 AI 对话入口完成复杂需求输入、对话纠正预算、摘要确认、自动规划与本机保存，无需进入高级表单。真实北京案例首日 4 站，地图返回的站间交通合计约 49 分钟；展示了实际加载的对应 POI 照片。这是路线 API 的估算，不是实地耗时，也不构成对原截图行程的等条件性能对比。
- 本机验收截图位于 `output/ux-itinerary.png`，合成测试均与真实接口证据分开。后续已修复地图构建配置读取：根目录 `.env` 原本已有 `VITE_AMAP_KEY`，先前构建遗漏了它。现同时读取根目录和应用目录配置，仅显式注入三个 `VITE_AMAP_*` 浏览器设置。生产构建通过，浏览器已实际显示高德底图、4 个景点标记及真实路线；截图为 `output/ux-map-fixed.png`。原 Key 未变，检查构建产物未发现后端地图、模型和搜索私钥。
- 浏览器实际将中山公园改为 09:00，重现与故宫同时开始导致的交通、活动重叠冲突；在同一预览改为 10:50 后冲突消失。`output/ux-conflict.png` 保存了冲突编辑器。若最终复核发现路线变化，会保留新预览供再次确认，不静默替换已保存行程。
- 加入交通缓冲和微小波动复核后，将同一草稿的中山公园设为 10:55，完成最终复核、本机提交，并刷新确认时间仍为 10:55、没有遗留待确认草稿。最终界面已更新到 `output/ux-itinerary.png`。
- 真实第三方服务可能超时、变更或缺少资料。长春北湖等地点能够取得营业信息，但本次没有足够官方票价依据时不会强行勾选。现有行程可通过“重新核验营业时间与门票”生成可审阅更新，仍需用户确认才能替换。
