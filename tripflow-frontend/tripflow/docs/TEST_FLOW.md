# TripFlow 前端测试流程

分三层，从快到慢依次执行。前两层不需要后端；第三层用契约测试桩代替 B 的后端。

## 1. 静态检查（约 10 秒）

```bash
cd apps/web
npx tsc -b          # 类型检查（含 packages/contracts、packages/context-engine）
npx eslint src
```

## 2. 单元测试（约 2 秒，20 项）

```bash
npm test
```

| 文件 | 覆盖 |
|---|---|
| `planOps.test.ts` | 原子提交 CAS、旧 revision 拒收（E02）、被替换草稿不能提交（E01）、硬冲突禁止提交、PARTIAL 需显式接受、撤销/重做 revision 递增、新编辑清空 redo、设置不进撤销栈、事实日志不随撤销回滚 |
| `engine.test.ts` | 进入+驻留→到达、持续离开→推定完成、短暂经过不触发、600m 精度与 5km 跳点被丢弃（E06）、页面隐藏→位置未知并恢复（E07）、WGS84↔GCJ02 转换（E14）、L3>L2>L1、去重（E09）、暂停只停 L1/L2、操作中暂缓普通卡、冷却 |
| `store.test.ts` | IndexedDB 落地与刷新恢复、多 tripId 隔离、存储失败时保留旧计划并报错、演示副本隔离且退出后无遗留（E16） |

## 3. 端到端验收流程（约 3 分钟，22 步）

```bash
# 终端 1：契约测试桩（非真实后端，数据全部标注为测试桩）
node tools/contract-stub/server.mjs
# 终端 2：前端
cd apps/web && npx vite --port 5173
# 终端 3：手机视口 390×844、触摸、zh-CN
python3 tools/e2e/acceptance.py ./acceptance-out
```

输出 `acceptance-out/report.md`、`report.json` 和每步截图。脚本依赖 Python Playwright 与 Chromium。

## 这套流程不能证明的事

以下仍需按 PRD §13 单独验收，不能用本流程结果代替：

- 真实高德地图、POI、路线，以及 B 的真实 Agent 与两家模型供应商（AC-03、AC-13、AC-15、AC-24）
- Android / iOS 真机触摸、HTTPS 下真实定位授权与前台到达（AC-08 真机部分、AC-20）
- Netlify + Render 公网访问、Cloudflare Tunnel 备用切换（AC-26）
- 断开外部 API、关闭后端 502、模型供应商失效（E11、E12）需要真实后端配合
